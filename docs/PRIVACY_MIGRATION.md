## 在任何清理之前

1. 私下保存完整 Git mirror，記錄參照與 checksum；不要把 mirror、舊 JSON 或正式隊員資料上傳公開 repository。獨立後端建立後，另做資料庫備份與還原演練。
2. 每台仍有資料的裝置下載舊版完整 JSON、名冊及本地賽程草稿。下載至私人位置，核對筆數與檔案 checksum。新版提供舊版原始鍵的下載，不會刪掉來源。
3. 明確列出受到影響的分支、標籤、PR、fork、Pages URL、協作者與部署方法，再由擁有者確認清理方式和維護時間。不能只因開發分支移除檔案就宣稱舊資訊已私密化。

## 遷移與驗證

- 在授權的天睿獨立後端完成安全設定後，使用登入頁的匯入流程；先下載匯入前工作區備份。比賽使用新 ID，來源事件／稽核另存，不重放原帳號的舊 outbox。
- 空名冊才自動接受舊名冊；已有雲端名冊時先人工比對。管理員可私下匯入賽程 JSON，校對後經 CAS 儲存，不能再發布公開 JSON。
- 第二台裝置用同一共用帳號登入，核對名冊、空白背號、賽程、比賽事件與統計。測試斷線、接手、衝突保留及完整還原。
- 在以上驗證與來源備份確認前，保留所有原始資料；不要清除瀏覽器儲存或以舊快照覆寫雲端。

## 待擁有者確認的清理選項

- 保留 Git 歷史：確認 repository 存取範圍與 GitHub Pages 方案／網址的影響，再決定是否改為私有或遷移靜態程式到不含舊資料的新位置。不可假定這會刪除已流出的副本。
- 清理歷史：只在私下備份與影響確認後，在獨立 mirror 上產生重寫的 dry run 與前後參照表。需另行授權才可能 force push；舊 PR／fork／GitHub 快取還需另作處理，必要時由擁有者聯繫 GitHub。
- 更新裝置與快取：新版本啟用時只清理舊程式 CacheStorage，不清掉 localStorage／IndexedDB 的球員與比賽；檢查仍未升級的裝置。已下載、截圖或外部保存的副本無法由程式遠端收回。

此次沒有 force push、歷史重寫、刪除正式資料、修改 main 或通知第三方。
