# DH、攻守互換與第三好球：實作及驗證

2026-11-12，接續 `dc677d0`／Draft PR #3，依[施工留言 #6818955426](https://github.com/YKC1117/tianrui-baseball-scorebook/pull/3#issuecomment-6818955426)。本輪保留既有介面、常用快記、拖曳排序、多守位、出席、賽程與資料；不施工 Firebase／帳號／同步，不改正式應用。

## 實際操作

1. 賽程 → 一鍵排陣 → 九棒與守備：「採用 DH」新場預設勾選；九棒選一位 DH，另外選先發投手。九棒及九守備共十位不同先發，DH 不守備、投手不打擊。未滿十人會阻擋開賽；關閉 DH 則為九棒九守備含投手。對手 DH 可獨立選擇。名單資格新增 DH，但守備缺口仍只匹配九個一般守位。
2. 換人與守備 → 更換投手：啟用 DH 時更換獨立投手保留全部九棒，二次登板另開投球段。換 DH 保留 DH 棒次。若讓打序球員投球、投手代打 DH 或 DH 進守備，先顯示變更、核對終止 DH；DH 進守備須明選投手接替的被換下守備員棒次。終止後不得重啟 DH，沒有推測二刀流例外。正規 DH 下投手只能代打 DH，不能代打其他守備員。
3. 紀分 S2 → 點一次「＋好球」：該球 +1，自動 K／一出局／下一棒，清 B/S，無多餘確認。按結果「三振」亦可；已知 S2 時只加決定球一次，未記完整球數時不猜補投球。兩好球界外球不增加三振。
4. 第三出局當下已換半局，通知明示「剛結束半局 → 已進入半局」。知道了只關閉通知，沒有第二次換局；最後半局顯示結束。復原第三出局同時恢復全部場況與通知。
5. 最近操作旁「改判未接捕」→ 打者最終壘包／出局 → 必要跑者選擇 → 原因待判或 WP／PB → 完成改判。一壘有人且不到兩出局不得選打者安全；兩出局或一壘空可依判決選擇。取消保留原 K；完成以單一操作取代原 K 的統計結果，K 成立、出局依判決，不計安打／RBI。第三出局未到一壘等情況取消到本壘得分，不增加第四出局。
6. WP／PB 不自動猜，PB 指定捕手；進階補記可改判原因並將數值移回原投手登板段／捕手，保留修改前後、時間、紀錄員。守備畫面、CSV、PNG 含 PB。

## 資料與原子操作

S3 將逐球及打席視為一次 snapshot／一次保存；復原一次即回到 S2 原場況，重做恢復整筆。未接捕改判使用精簡的前打席快照及場況指紋；不遞迴嵌入整場歷史。新增後續記錄會關閉過期改判入口，避免覆蓋後續比賽。

改判保留原事件為「已改判」及替代事件關聯，只有一筆有效打席，不重複 PA／AB／BF／SO／投球數。修正第三出局可以回到原半局；連最終半局的自動結束亦可依合法未接捕結果回復。重新開頁仍必填姓名，單場 JSON 重新產生 ID 不會破壞合法改判快照。

舊場無 DH 標記保持相容，不強迫把舊九棒或空守位轉換為新規格；新場則明確標記 `standard-9` 並驗證角色。舊名單缺守位仍可匯入、空背號及本場支援保留。預覽只寫 `TR_UI_REVIEW_SANDBOX_V1`，不讀寫正式資料鍵。儲存失敗仍保留最後已存資料，顯示未保存並可匯出記憶體中的救援備份。

另修復自足 HTML 打包使用字串替換時誤解 `$&` 的問題；改用回呼插入完整程式，實際開啟及下載位元組一致性納入測試。

## 驗證

- `npm test`：56 項 Node 測試，含 13 項新增規則／真實記分引擎測試。主客隊 DH 九棒完整循環均不增加獨立投手 PA／AB；非 DH 舊場、新場、換投／換人／終止、快照匯入、S3 復原重做、投球及打席歸屬均核對。
- `TR_WEBKIT_EXECUTABLE=/workspace/work/webkit-run.sh npm run test:ui`：165 案例（33 × Chromium 手機／平板／桌面、WebKit 手機／平板）。新增 9 個完整流程：DH 開賽／關閉、換投二次登板、終止 DH、S3 單點、上下半局／結束／復原、未接捕原因補判／JSON／CSV／PNG、占一壘限制、第三出局取消得分、125% 文字及儲存失敗。
- 320／390 px 的文字放大測試實際把儲存設定設為 1.25，並檢查渲染後根字級 22.5 px，避免只改 CSS 後被重繪重設。另以兩個手機瀏覽器專案補跑該情境。
- `scripts/verify-ui-preview.mjs <網址>`：以兩引擎的原生 touch tap 走查原七種快記情境，增加實際 DH 換投、S3 第三出局、通知關閉、改判 WP 上壘；核對計數、無頁面錯誤／後端請求、下載相同 HTML、重設及備份還原、正式舊儲存鍵不變。
- UI CI 自動跑上述 Node／瀏覽器流程及自足 HTML／模擬資料重建一致性；最新提交的實際結果、版本 SHA 及公開網址記於 PR。

這是瀏覽器自動化與原生觸控點按，不等同 iPhone／iPad 原生 Safari 真機驗收。未接 Firebase 或其他正式後端，沒有多人同步驗收主張。延長賽與二刀流等其他賽制不在本輪新增，沿用原本九局／提前結束機制。

## 試用與發布

由 Draft PR 的版本化直接網址開啟 `https://ykc1117.github.io/tianrui-baseball-scorebook/preview/tianrui-ui-preview.html?v=工程提交SHA`，或在試用設定下載完整 HTML 備份。全部是合成球員及賽事，不需要任何帳號設定。

依留言明確授權，發布 main 時僅更新 `preview/tianrui-ui-preview.html`；使用獨立發布工作樹，檢查唯一差異路徑及其餘全部 blob／mode 不變，不合併 UI 分支、不修改正式首頁／Logo／service worker。公開回傳須與已測 HTML 位元組相同，並對實際網址再執行 touch 走查。工程提交、獨立預覽發布提交、CI 及核驗結果以 PR 最新交付紀錄為準。

規則來源：[OBR 2026](https://cdn2.sportngin.com/attachments/document/0095/4660/2026-official-baseball-rules.pdf) 5.05(a)(2)、5.11(a)(5)/(7)/(10)/(12)；[MLB DH 說明](https://www.mlb.com/glossary/rules/designated-hitter-rule)。球隊原有可再登板的統計保留，沒有擅自套用不同聯盟的禁止再登板規則。
