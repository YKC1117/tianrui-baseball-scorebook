# 比賽現場快速記分：施工與走查報告

接續 UI Draft PR #3／`a4c9a13`，依 [施工留言 #6808425004](https://github.com/YKC1117/tianrui-baseball-scorebook/pull/3#issuecomment-6808425004) 修正。原本所有結果一律呼叫大型 `playOpen()` 表單；現在由快速判斷層決定直接提交或詢問必要跑壘結果，仍使用原 `commitPlay()` 的打擊／投球統計增量與登板段歸屬。詳細模式保留。

只有合成球員與賽事；不連 Firebase、帳號或資料庫。沿用原 Logo、多守位、賽程及分場草稿。

## 如何操作

- 預設「快速記分」。常用結果直接點；未顯示的結果在「全部結果」。
- 「編輯常用」可勾選全部 15 種結果中的任意組合，不限六種；可隱藏、長按把手拖曳、用 ↑／↓ 移動，調整每列 2／3 顆及優先顯示數量，並恢復預設。
- 從球員文字區可正常捲動；只有把手接管拖曳手勢，需長按 300 ms 才開始，取消拖曳會還原順序。編輯鍵沒有記分動作。
- 配置存在預覽 `db.settings.quickScoring`，重開及完整 JSON 備份還原保留。舊版設定沒有此欄位時採快速模式預設，不清除舊資料。
- 已記錄狀態與「復原／重做」在主操作區；儲存中、成功、失敗分開顯示。失敗時保留畫面草稿並能下載救援備份。
- ER、守備記號及備註不再擋住快速記分。在「進階補記／賽後修正」調整新打席的 RBI、自責判定與文字；原值、修改後值、時間及紀錄員保留。PO／A／E 仍使用「補登守備」，不從不明確的記號猜守備球員。

## iPhone 尺寸逐步走查

以下從已開啟比賽、完成紀錄員姓名後計算；不把建立比賽或編輯常用列入每打席步數。正常路徑不含故意漏填／錯填的驗證測試。採 WebKit iPhone 尺寸 390×844、320 px；另檢查 320×740 與 390×740。

| 現場情境 | 依序操作 | 必要點擊 | 資料與畫面結果 |
|---|---|---:|---|
| 空壘 BB | 點「四壞保送」 | 1 | 打者一壘、PA／BB／BF 各 +1，AB 不增；無確認視窗、留主畫面 |
| 空壘 SO | 點「三振」 | 1 | 打者出局、SO／BF／PA 及投手出局數正確；第三出局由原引擎換半局 |
| 空壘 1B | 點「一壘安打」 | 1 | 打者一壘、H／1B／AB／PA／投手被安打正確；不猜額外進壘 |
| 空壘 HR | 點「全壘打」 | 1 | 打者 R／RBI／HR 各 +1，投手 R +1；ER 保留待判 |
| 滿壘 BB | 點「四壞保送」 | 1 | 僅被迫進壘；三壘跑者得分、打者 +1 RBI，新一至三壘無重疊 |
| 二壘有人，1B 後停三壘 | 點 1B → 跑者「三壘」→ 完成紀錄 | 3 | 初開面板沒有預選跑者去向；得分、RBI 都不增，回主畫面不跳捲動 |
| 二壘有人，1B 後得分 | 點 1B → 跑者「得分」→ 選 RBI → 完成紀錄 | 4 | 必須明確選 RBI；漏選會保留面板且不寫入 |
| 一出局，一壘有人，雙殺 | 展開全部結果 → 雙殺 → 跑者出局 → 完成紀錄 | 4（常用鍵已配置時 3） | 本次兩出局、雙殺統計、投手出局及半局切換一致 |
| 第三出局同時到本壘 | 選跑者結果 → 指明封殺／非封殺時間先後 → 必要時選 RBI → 完成 | 視實際跑者數 | 未作必要判決不寫入；封殺／打者未到一壘的得分取消，不虛增第四個出局 |
| 誤點快速結果 | 點「復原」 | 1 | 原比分、壘況、打者與投手數據還原；可再重做 |

首屏保留比分、局數上下、出局、壘況、打者、B／S／O、壞／好／界外球、常用結果及復原。在上述 320／390 px、740 px 高度的預設六鍵配置，主要記分鍵的邊界位於底部導覽上方，不需要來回捲動；自訂更多鍵可用「優先顯示」控制主畫面長度。選單文字至少 16 px，避免手機輸入自動放大的常見問題。

## 規則與數據驗證

- 8 種壘況 × BB／IBB／HBP：只推進被迫跑者，只有滿壘強迫得一分與一打點。也修正詳細模式滿壘保送預設 RBI=0 的原問題。
- 空壘 BB／IBB／HBP／SO／GO／FO／1B／2B／3B／HR 共用原統計核心；已核對打者、跑者、得分、打點、投手 BF／被安打／保送／三振／出局／ER 待判。
- 有人在壘的非確定結果，跑者去向不預選；重疊壘包、退壘、未選跑者、過多出局及未確認 RBI 不提交。
- 雙殺必須兩位出局；兩出局不允許再錄雙殺。雙殺打不計 RBI；非第三出局時可依實際判決記合法得分。
- 第三出局與得分同時發生時，非明確的情況必須確認封殺或得分先後；取消的到本壘不計分、不加 RBI，也不當成額外出局；判決類型與取消得分數保存在該打席事件。封殺不能保留安打分類，可保留跑壘選擇直接改記野手選擇；帶打點的飛球接殺提示改選高飛犧牲打，保留正確 AB／SF 分類。
- 快速打席有 600 ms 防連點，逐球同鍵有 250 ms 防重複；同步的非同步權限返回也檢查原場上狀態，避免重複提交。這是防誤觸保護，不代表多人同步驗收。
- 復原／重做、B／S／界外兩好球上限、重載、全備份與失敗救援均實際驗證。補判 ER 可追溯到原責任投手的原登板段，重返投手不會把修正記到新登板段。
- 故意模擬儲存空間不足：最後已保存資料不變，新草稿顯示「尚未保存」，仍能下載救援備份。

## 測試範圍與限制

Node 43 項；瀏覽器 120 案例：Chromium 手機／平板／桌面、WebKit 手機／平板。包含原有 80 案例及新增快記、實際步數、常用設定、觸控排序、保存還原、RBI／第三出局與補記。

拖曳測試：Chromium 使用原生 CDP 多點觸控事件序列；WebKit 使用 `pointerType=touch` 的 Safari PointerEvent 序列，沒有用 desktop mouse 代替手機拖曳。Playwright WebKit 的公開 API 只有觸控點按，這不構成 iPhone／iPad 原生 Safari 真機驗收；本輪沒有假稱真機已通過。

UI Draft PR 的最終 Checks 與說明記錄實際結果、提交 SHA 及最新入口。原後端流程依要求停跑。根目錄 README 及 Firebase 程式不修改。

## 隔離發布與快取

獨立試用檔為 `preview/tianrui-ui-preview.html`，不需要任何服務設定。發布時另建 main 工作樹，只提交這一個檔案；在推送前檢查相對父提交唯一差異路徑，並核對其餘全部檔案的 Git blob ID 完全一致。不將 UI 工程分支合併 main。

既有正式 service worker 會快取同源檔案，因此交付 `/preview/tianrui-ui-preview.html?v=新提交` 的直接網址，避免舊試用快取；離線 HTML 下載亦保留同一版本查詢參數。發布完成後須比較公開回傳 HTML 與測試產物位元組，並實際開啟走查，才可宣稱新版已上線。正式首頁、程式、Logo、賽程、資料與 service worker 不覆寫。

可重跑公開網址的原生觸控點按走查：`node scripts/verify-ui-preview.mjs <最新預覽網址>`。工具在新的瀏覽器環境只寫入試用儲存鍵，逐一核對 7 種情境的實際點擊數、數據、無額外視窗、捲動位置、舊儲存鍵與離線下載位元組；報告結果見 PR。
